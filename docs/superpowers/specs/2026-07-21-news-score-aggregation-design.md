# 利好利空总分聚合算法优化（方案 A：条数占比法）

- 日期：2026-07-21
- 涉及项目：数据大盘 / StockRank（backend + frontend）
- 状态：待审查

## 1. 背景与问题

"今日利好利空分布"面板中心显示一个 0–100 的综合总分（50=中性）。用户反馈：**今天利好新闻明显多于利空，总分却只有五十多分，不够"明显"。**

### 1.1 当前机制

1. 每条新闻由 AI 打 0–100 分（`NEWS_ANALYSIS_PROMPT`，[ai_analyzer.py:637](../../../backend/ai_analyzer.py)）。单条分类阈值（[news_score_thresholds.py](../../../backend/news_score_thresholds.py)）：≥55 利好、≤45 利空、46–54 中性。
2. 今日总分在 [/api/news/score-trend](../../../backend/routes/news_routes.py) 接口内实时计算（非持久化），逻辑为：**所有方向性新闻（利好+利空）单条分数的简单算术平均，中性不计入**。
3. 倾向标签：总分 ≥55 "偏利好"、≤45 "偏利空"、中间 "多空均衡"。

> 注：`config/ai_prompt.txt` 不是打分提示词，它只做"重大/一般"判断、不输出分数。打分提示词是代码内的 `NEWS_ANALYSIS_PROMPT`。

### 1.2 真实数据验证（2026-07-21）

| 类别 | 条数 | 平均分 | 区间 |
|---|---|---|---|
| 利好 | 91 | 67.7（中利好）| 55–95 |
| 利空 | 37 | 31.9（中利空）| 18–45 |
| 中性 | 215 | — | 不计入 |

当前总分 = `(91×67.7 + 37×31.9) / 128 = 57`。

### 1.3 根因

简单平均下，总分 ≈ `50 + (利好均值−50)×利好占比 − (50−利空均值)×利空占比`。

今日利好偏离 +17.7、利空偏离 −18.1，**两者强度几乎对称、相互抵消**，总分只剩条数占比的温和线性影响：`50 + 17.7×0.71 − 18.1×0.29 ≈ 57`。

结论：
- AI 打分正常（利好 67.7、利空 31.9 完全符合提示词设定的"中利好/中利空"档），**提示词不是瓶颈**。
- 瓶颈是**聚合算法把"91 vs 37"这个最直观的多空对比信号稀释了**。

## 2. 设计目标

让利好/利空的**条数对比**直接、明显地反映到总分上，同时不丢失强度信息。改动面最小、零魔法参数、历史数据天然兼容。

## 3. 方案：条数占比法（已选定）

### 3.1 核心算法

总分由"方向性新闻的净利好占比"决定：

```
overall_score = 50 + (利好条数 − 利空条数) / (利好条数 + 利空条数) × 50
```

- 今日验证：`50 + (91−37)/128 × 50 = 71`（明显偏利好）。
- 公式天然落在 [0,100]：`(pos−neg)/(pos+neg) ∈ [−1,1]` → 结果 ∈ [0,100]，无需 clamp。
- 语义：50=多空均衡；利好占比 71% → 71 分，与饼图视觉一致。

### 3.2 边界保护（`MIN_DIRECTIONAL_SAMPLES = 5`）

方向性新闻（利好+利空）少于 5 条时，占比会被偶然极端化（如 2 条全利好→100 分不合理），此时**回退到原来的强度平均法**：

```
if 方向性条数 >= 5:
    overall_score = 条数占比法
else:
    overall_score = 强度平均法（原逻辑）  # 无方向性数据时为 50
```

`MIN_DIRECTIONAL_SAMPLES` 提为模块级常量，便于后续调参。

### 3.3 强度信息补偿

方案 A 本身不含强度信息。为弥补，`summary` 增加两个辅助字段：

- `avg_positive_score`：利好新闻平均分（今日 67.7 → 显示 68）
- `avg_negative_score`：利空新闻平均分（今日 31.9 → 显示 32）

前端在总分数字下方加一行小字：`利好均 68 · 利空均 32`。强度信息从"总分"迁移到"辅助指标"，**零丢失**。

实现要点：当前代码只收集了 `all_scores`（所有方向性分数）和 per-bucket `scores`，需新增 `pos_scores` / `neg_scores` 两个列表分别收集，用于计算上述均值。

### 3.4 倾向标签阈值：保持不变

`≥55 偏利好 / ≤45 偏利空 / 中间多空均衡` 不调整。方案 A 下今日 71 分已明显落入"偏利好"，数字本身已足够明显，无需靠加档位标签强化。

## 4. 改动点

### 4.1 后端（必改）

文件：`backend/routes/news_routes.py`，函数 `get_news_score_trend`（226 行起）

1. **新增常量**（模块级）：`MIN_DIRECTIONAL_SAMPLES = 5`。
2. **收集分组分数**（318-336 行附近）：在遍历中新增 `pos_scores` / `neg_scores`，分别 append 利好 / 利空分数。
3. **改写总分计算**（372-376 行）：按 3.1 / 3.2 用 `total_positive` / `total_negative` 计算条数占比，不足 5 条回退强度平均。
4. **summary 增字段**（408-415 行）：加 `avg_positive_score`、`avg_negative_score`。

### 4.2 前端（小改）

文件：`frontend/src/components/NewsPage/NewsPage.script.js` + 对应模板/样式

- 饼图中心区在 `overall_score` / `tendency` 下方追加一行小字，读取 `summary.avg_positive_score` / `avg_negative_score` 展示 `利好均 X · 利空均 Y`。
- 总分数字与倾向标签**无需改动**（自动从后端取值，57→71 自动生效）。

### 4.3 不动的部分

- AI 打分提示词 `NEWS_ANALYSIS_PROMPT`（[ai_analyzer.py:637](../../../backend/ai_analyzer.py)）
- 单条分类阈值 `classify_score` 及 `news_score_thresholds.py`（55/45）
- 饼图占比、柱状图分桶统计
- `config/news_analysis_cache.json` 及所有持久化数据
- 总分是实时计算的，**历史数据天然兼容，无需重新分析任何新闻**

## 6. 影响评估

- **风险**：低。仅改一个接口的聚合计算 + 前端一处展示，无数据迁移、无 AI 重跑。
- **可逆**：算法集中在 `get_news_score_trend` 内，回退简单。
- **副作用**：总分语义从"平均强度"变为"多空数量对比"，已通过均分小字补偿强度信息。
