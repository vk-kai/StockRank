# 缠论画笔策略设计

## 1. 文档目的

本文档基于 `zen_doc/缠论.txt` 中关于分型、包含关系、笔、线段的原文内容，整理出一套适合程序实现的“自动画笔”设计方案。

目标不是泛泛介绍缠论，而是明确回答下面几个问题：

1. 什么叫一笔。
2. 分型怎么找。
3. 包含关系怎么处理。
4. 相邻同类分型怎么处理。
5. 画笔在实时行情里如何确认、如何延伸、如何修正。
6. 后续写代码时，数据结构、状态机、边界条件应该怎么设计。

本文重点面向“自动画笔”，因此会在尊重原文的前提下，给出明确、可编码、可回测、可调参的工程定义。

## 2. 原文规则来源

本设计主要依据 `缠论.txt` 中以下内容提炼：

1. 第 62 课《分型、笔与线段》
2. 第 63 课《替各位理理基本概念》
3. 第 64 课中关于精度、缺口、线段确认的补充
4. 第 65 课《再说说分型、笔、线段》
5. 后续问答中关于“新笔定义”的再次确认

原文中与自动画笔最相关的核心思想如下：

1. 顶分型和底分型要先在“去包含”的 K 线序列上识别。
2. 一笔必须由相邻的一顶一底构成。
3. 顶底之间不能共用 K 线。
4. 原始定义要求顶底之间至少有独立 K 线。
5. 后续作者放宽为“顶分型最高 K 线与底分型最低 K 线之间，至少有 3 根原始 K 线”。
6. 相邻同类分型之间，如果中间没有形成有效反向分型，则前一个分型可忽略，只保留更有意义的那个。
7. 自动划分必须在统一精度下进行，精度一旦选定，不能中途变化。

## 3. 设计原则

### 3.1 原则一：先统一精度，再统一规则

缠论原文明确强调，精度不是绝对唯一的，但一旦设定必须一致。因此程序设计中，第一步不是画笔，而是定义价格比较规则。

建议提供统一的价格归一化函数 `normalize_price()`，例如：

1. `strict`：不做处理，直接使用原始价格。
2. `round_tick`：按最小报价单位取整。
3. `round_n`：保留到小数点后 `n` 位。
4. `tolerance`：价差绝对值小于某阈值时视为相等。

推荐默认方案：

1. 股票日线、分钟线：直接使用原始价格，保留到数据源精度。
2. 如果不同数据源之间存在极小偏差，可增加 `tolerance`，但要全流程一致。

### 3.2 原则二：先处理包含，再找分型，再成笔

顺序不能乱：

1. 原始 K 线序列
2. 去包含后的标准 K 线序列
3. 在标准 K 线序列上找顶底分型
4. 在分型序列上生成笔

### 3.3 原则三：笔是“确认对象”，不是“预测对象”

自动画笔应当区分两种状态：

1. 已确认笔：两端分型都已经成立，并满足画笔规则。
2. 未完成笔：当前只有起点，终点仍在延伸。

这点很重要，因为实盘界面通常既要显示“确认笔”，也要显示“临时笔”。

### 3.4 原则四：建议同时支持严格笔和新笔

原文先给了严格定义，后面又给了放宽后的“新笔定义”。因此工程上不要写死一种口径，建议支持：

1. `strict_pen`
2. `relaxed_pen`

默认建议使用 `relaxed_pen`，因为原文后续明确将其作为更适合处理复杂分段的定义。

## 4. 核心对象定义

## 4.1 原始 K 线 `RawBar`

字段建议：

```python
class RawBar:
    index: int
    dt: datetime
    open: float
    high: float
    low: float
    close: float
    volume: float
```

## 4.2 标准 K 线 `StdBar`

标准 K 线是经过包含处理后的 K 线。它不是简单复制原始 K 线，而是“合并产物”，所以必须保留来源映射。

字段建议：

```python
class StdBar:
    index: int
    high: float
    low: float
    source_start: int
    source_end: int
    raw_indices: list[int]
```

说明：

1. `source_start` 和 `source_end` 用来映射回原始 K 线。
2. 以后判断“是否共用 K 线”“中间隔了多少根原始 K 线”，都依赖这个映射。

## 4.3 分型 `Fractal`

字段建议：

```python
class Fractal:
    index: int
    type: str   # 'top' or 'bottom'
    std_bar_index: int
    left_std_index: int
    mid_std_index: int
    right_std_index: int
    price: float
    raw_start: int
    raw_end: int
    core_raw_index: int
    confirmed: bool
```

说明：

1. 顶分型的 `price` 取中间标准 K 线的高点。
2. 底分型的 `price` 取中间标准 K 线的低点。
3. `core_raw_index` 用于表示该分型真正对应的核心原始 K 线位置。
4. `raw_start/raw_end` 表示该分型覆盖到的原始 K 线范围。

## 4.4 笔 `Pen`

字段建议：

```python
class Pen:
    index: int
    direction: str  # 'up' or 'down'
    start_fractal_index: int
    end_fractal_index: int
    start_price: float
    end_price: float
    start_raw_index: int
    end_raw_index: int
    confirmed: bool
```

说明：

1. 底分型到顶分型，构成向上一笔。
2. 顶分型到底分型，构成向下一笔。

## 5. 包含关系处理

## 5.1 什么叫包含关系

对于相邻两根 K 线 `A`、`B`：

1. 如果 `A.high >= B.high and A.low <= B.low`，则 `A` 包含 `B`。
2. 如果 `A.high <= B.high and A.low >= B.low`，则 `B` 包含 `A`。

只要出现上述任一种，都视为存在包含关系。

## 5.2 包含处理规则

原文规定：

1. 向上时，取两根 K 线的高点较高者作为新高点，低点较高者作为新低点。
2. 向下时，取两根 K 线的低点较低者作为新低点，高点较低者作为新高点。

写成程序：

### 向上合并

```python
new_high = max(bar1.high, bar2.high)
new_low = max(bar1.low, bar2.low)
```

### 向下合并

```python
new_high = min(bar1.high, bar2.high)
new_low = min(bar1.low, bar2.low)
```

## 5.3 “向上”还是“向下”怎么确定

这是工程实现里最容易写错的地方。

建议按原文第 65 课的顺序原则处理：

1. 只处理相邻包含关系。
2. 处理时必须按时间顺序逐根推进。
3. 如果当前 bar 与前一标准 bar 发生包含，则需要根据最近一个“非包含方向”决定合并方向。

推荐实现口径：

1. 如果最近一次有效移动表现为高点和低点同时上移，则方向记为 `up`。
2. 如果最近一次有效移动表现为高点和低点同时下移，则方向记为 `down`。
3. 若当前序列开头就发生包含，无法判断方向，则使用最近两根非完全相等原始 K 线推断。
4. 若仍无法判断，暂时延后，直到方向明朗后再合并。

更稳妥的工程方案：

1. 维护 `last_direction in {up, down, unknown}`。
2. 一旦方向确定，在连续包含链中沿用该方向。
3. 每次合并形成新 `StdBar` 后，再与下一根继续判断是否包含。

## 5.4 连续包含链处理

原文强调：包含关系不满足传递律，因此必须顺序处理，不能一次性把多根 K 线直接按全局最高最低去算。

正确流程：

1. 先处理第 1、2 根是否包含，若包含则合并成新 bar。
2. 再用新 bar 和第 3 根比较。
3. 若仍包含，继续合并。
4. 若不包含，则输出当前标准 K 线，进入下一轮。

## 5.5 包含处理的输出要求

每一个 `StdBar` 必须带完整来源：

1. 包含了哪些原始 K 线。
2. 合并后的高低点。
3. 合并方向。

因为后续分型共线判断、笔间 K 线数量判断，都要回到原始序列。

## 6. 分型识别规则

## 6.1 顶分型

在去包含后的标准 K 线序列中，连续三根 `A, B, C` 满足：

1. `B.high > A.high`
2. `B.high > C.high`
3. `B.low > A.low`
4. `B.low > C.low`

则 `B` 为顶分型。

## 6.2 底分型

在去包含后的标准 K 线序列中，连续三根 `A, B, C` 满足：

1. `B.low < A.low`
2. `B.low < C.low`
3. `B.high < A.high`
4. `B.high < C.high`

则 `B` 为底分型。

## 6.3 关于等于号的工程处理

原文偏重几何唯一性，但在真实数据里会出现完全相等或近似相等的高低点。建议：

1. 在完成价格归一化后，分型比较默认使用严格不等号。
2. 若出现相等，默认不形成分型，等待后续 K 线继续确认。
3. 不建议在分型判定中直接使用 `>=` 或 `<=`，否则容易产生连续重复分型。

这样做的好处是程序行为更稳定，画笔不会因为平台式相等高低点出现大量毛刺。

## 6.4 分型确认时点

一个分型必须在第三根标准 K 线走完后才能确认。

也就是说：

1. 顶分型不是在中间那根出现时确认。
2. 而是在右侧那根标准 K 线完成后确认。

实盘中这意味着分型确认天然有一根标准 K 线的延迟。

## 6.5 分型映射回原始 K 线

自动画笔必须能把标准分型映射回原始 K 线，否则无法实现后面的“新笔定义”。

推荐规则：

1. 顶分型核心原始 K 线取其中间标准 K 线所覆盖原始 K 线中，最高点对应的那根。
2. 底分型核心原始 K 线取其中间标准 K 线所覆盖原始 K 线中，最低点对应的那根。
3. 若最高或最低出现多根并列，取最靠后的那根，保证实时更新时更稳定。

## 7. 笔的定义

## 7.1 原始严格笔定义

根据第 62 课，严格定义下：

1. 一笔由相邻的顶和底构成。
2. 顶底之间不能共用 K 线。
3. 顶底之间至少要有独立 K 线。

对应到程序可理解为：

1. 顶分型与底分型类型必须相反。
2. 它们在分型序列中必须相邻，中间不存在其他有效分型。
3. 两个分型覆盖的原始 K 线集合不能交叉。
4. 两个分型核心 K 线之间至少还要隔着 1 根独立原始 K 线。

## 7.2 放宽后的新笔定义

原文后续明确给出新的成立条件：

1. 顶分型与底分型经过包含处理后，不允许共用 K 线。
2. 在满足 1 的前提下，顶分型中最高 K 线和底分型中最低 K 线之间，不考虑包含关系，至少有 3 根原始 K 线。

这是本文推荐的默认实现。

## 7.3 我们建议采用的程序化笔定义

默认采用 `relaxed_pen`，具体规则如下：

1. 只允许一顶一底配对。
2. 顶底必须在经过“同类分型去噪”后的有效分型序列中相邻。
3. 两个分型覆盖的原始 K 线范围不能重叠。
4. 用两个分型的核心原始 K 线计算间隔，二者之间的原始 K 线数量必须大于等于 3。
5. 底到顶为上笔，顶到底为下笔。

这里第 4 条用公式表示：

```python
gap_count = abs(f2.core_raw_index - f1.core_raw_index) - 1
is_valid = gap_count >= 3
```

说明：

1. `gap_count` 统计的是两个核心原始 K 线之间，不包含两端本身的原始 K 线数量。
2. 这正对应原文“顶分型最高 K 线和底分型最低 K 线之间（不包括这两 K 线）至少有 3 根 K 线”。

## 7.4 为什么不要直接用标准 K 线数量判断

因为原文在这里特别写了“不考虑包含关系”，说明画笔间隔的计数应回到原始 K 线，而不是合并后的标准 K 线。

因此程序中必须保留：

1. 标准 K 线到原始 K 线的映射
2. 分型核心原始 K 线索引

否则新笔定义没法严格实现。

## 8. 同类分型处理规则

这是自动画笔中第二容易写错的地方。

## 8.1 相邻同类分型不能直接成笔

如果连续出现：

1. 顶分型后又出现顶分型
2. 底分型后又出现底分型

那它们不能直接构成笔，因为笔必须是一顶一底。

## 8.2 中间没有反向有效分型时，前一个可忽略

根据第 65 课的原文：

如果两个同类分型之间没有其他顶底结构足以形成有效反向转折，那么前一个分型可以忽略。

工程化处理建议：

1. 对连续两个顶分型，保留高点更高的那个。
2. 对连续两个底分型，保留低点更低的那个。
3. 被替代的那个分型不参与成笔。

这是最符合“保留更强拐点”的程序实现方式。

## 8.3 为什么这样处理

缠论原文的意思是：

1. 如果中间没有形成足够级别的反向结构，那么先前那个同类分型不值得作为独立分析对象。
2. 自动画笔本质上是在分型序列上做一次“有效拐点压缩”。

因此，在编码上可把这一步称为：

1. 分型净化
2. 分型去噪
3. 分型压缩

## 9. 自动画笔完整流程

下面给出推荐实现流程。

## 9.1 第一步：预处理原始 K 线

1. 读取原始 K 线序列。
2. 对价格做统一精度归一化。
3. 保证时间升序排列。
4. 去掉明显脏数据，如 `high < low` 的异常记录。

## 9.2 第二步：生成标准 K 线序列

1. 从左到右扫描原始 K 线。
2. 若与当前标准 K 线无包含关系，则直接新增标准 K 线。
3. 若有包含关系，则根据当前方向进行合并。
4. 连续包含时持续顺序合并。

## 9.3 第三步：识别标准分型

1. 在标准 K 线序列上，用滑动窗口 3 根识别顶底分型。
2. 每识别出一个分型，就映射回原始 K 线。
3. 记录分型覆盖范围和核心原始 K 线位置。

## 9.4 第四步：做分型净化

1. 若当前分型与前一个有效分型类型不同，进入成笔候选。
2. 若当前分型与前一个有效分型类型相同：
3. 顶分型比较高点，保留更高的。
4. 底分型比较低点，保留更低的。

## 9.5 第五步：按笔规则连接分型

对净化后的分型序列从左到右扫描：

1. 若前后分型类型相反，则尝试成笔。
2. 检查是否共用原始 K 线。
3. 检查是否满足间隔 K 线数量要求。
4. 满足则生成一笔。
5. 不满足则按“更强端点优先”继续更新候选分型。

## 9.6 第六步：维护未完成笔

实时行情中，最后一笔往往未完成。建议：

1. 已确认笔存入 `confirmed_pens`
2. 当前延伸中的笔存入 `active_pen`

`active_pen` 的终点可以随着新高新低持续变化，但只有当反向分型确认并满足笔规则时，上一笔才真正封闭。

## 10. 实时状态机设计

建议用状态机写，避免逻辑混乱。

## 10.1 状态定义

```python
class PenState(Enum):
    SEEK_START = 1
    SEEK_END = 2
    EXTENDING = 3
```

## 10.2 状态含义

### `SEEK_START`

还没有找到有效起点分型。

### `SEEK_END`

已经找到起点分型，等待相反分型形成候选终点。

### `EXTENDING`

已经形成临时笔，但终点还可能被更强的同类分型替换。

## 10.3 实时更新规则

每来一根新原始 K 线：

1. 更新标准 K 线序列。
2. 若新增标准 K 线，则尝试确认新分型。
3. 若出现新分型，则进入分型净化逻辑。
4. 若分型净化后得到新的有效拐点，则尝试更新画笔。

具体更新逻辑：

1. 如果新分型与当前候选终点同类，且更极端，则替换终点。
2. 如果新分型与当前候选终点异类，并满足成笔条件，则确认上一笔。
3. 之后以该新分型作为下一笔起点，继续循环。

## 11. 笔的延伸与修正

自动画笔不是静态问题，关键在于最后一笔怎么变。

## 11.1 未确认终点可以被替换

例如当前正在寻找上笔终点：

1. 先出现一个顶分型 A
2. 后面又出现更高的顶分型 B
3. 且 A 与 B 之间没有形成有效底分型

则：

1. A 不作为最终笔终点
2. 用 B 替换 A

## 11.2 已确认笔一般不回改

一旦一笔已经由两个确认分型构成，并且后续又出现了满足规则的反向笔，则这笔应视为历史确认结果，不再回溯改写。

否则在回测和实盘中会出现严重的“未来函数”问题。

## 11.3 最后一笔允许显示为虚线

建议前端图形上区分：

1. 确认笔：实线
2. 未确认笔：虚线

这样最符合实盘观察习惯。

## 12. 缺口处理建议

原文对缺口的说明主要是线段层面的，但对画笔也有指导意义。

建议：

1. 缺口本身不单独定义成笔。
2. 仍然只按 K 线高低点、包含关系、分型规则来识别笔。
3. 如果缺口顺着原笔方向延续，则仍属于原笔内部波动。
4. 不要因为“跳空”就人为拆出一笔。

也就是说，自动画笔阶段尽量不要加入“跳空特殊画笔”规则。

## 13. 参数化建议

为了后续调试和回测，建议把关键逻辑参数化。

## 13.1 必要参数

```python
class PenConfig:
    pen_mode: str                  # strict_pen / relaxed_pen
    price_mode: str                # strict / round_tick / round_n / tolerance
    round_digits: int | None
    tolerance: float | None
    fractal_strict: bool           # True: 严格不等
    replace_equal_extreme: bool    # 极值相等时是否允许后者替换前者
```

## 13.2 推荐默认值

```python
PenConfig(
    pen_mode="relaxed_pen",
```

## 14. 推荐伪代码

```python
def build_pens(raw_bars, config):
    raw_bars = normalize_bars(raw_bars, config)
    std_bars = build_standard_bars(raw_bars, config)
    fractals = detect_fractals(std_bars, raw_bars, config)
    clean_fractals = compress_fractals(fractals, config)

    pens = []
    current = None

    for fx in clean_fractals:
        if current is None:
            current = fx
            continue

        if fx.type == current.type:
            current = choose_stronger_same_type(current, fx)
            continue

        if is_valid_pen(current, fx, raw_bars, config):
            pens.append(make_pen(current, fx))
            current = fx
        else:
            current = resolve_invalid_pair(current, fx)

    return pens
```

### `is_valid_pen()` 推荐实现

```python
def is_valid_pen(f1, f2, raw_bars, config):
    if f1.type == f2.type:
        return False

    if overlap(f1.raw_start, f1.raw_end, f2.raw_start, f2.raw_end):
        return False

    gap_count = abs(f2.core_raw_index - f1.core_raw_index) - 1

    if config.pen_mode == "strict_pen":
        return gap_count >= 1

    if config.pen_mode == "relaxed_pen":
        return gap_count >= 3

    return False
```

## 15. 边界场景与处理规则

## 15.1 场景一：顶底分型共用 K 线

处理：

1. 直接判为不能成笔。
2. 等待后续更远的反向分型。

## 15.2 场景二：相邻反向分型，但间隔不足

处理：

1. 严格笔模式下，间隔小于 1 根，不成笔。
2. 新笔模式下，间隔小于 3 根，不成笔。

## 15.3 场景三：连续两个顶分型

处理：

1. 保留高点更高的顶分型。
2. 若高点相等，可保留后者，便于实时更新。

## 15.4 场景四：连续两个底分型

处理：

1. 保留低点更低的底分型。
2. 若低点相等，可保留后者。

## 15.5 场景五：最后一个分型尚未确认

处理：

1. 不计入确认笔。
2. 仅作为临时显示对象。

## 15.6 场景六：一开始就出现包含关系

处理：

1. 先缓冲前几根 K 线。
2. 待方向可判定后再进行标准 K 线合并。

## 15.7 场景七：平台式横走，频繁相等高低点

处理：

1. 价格先归一化。
2. 分型使用严格不等。
3. 避免在平台震荡里制造伪分型。

## 17. 推荐实现口径总结

如果你要马上开始写“自动画笔”代码，我建议直接采用下面这套口径：

1. 先做原始 K 线统一精度处理。
2. 按顺序生成去包含后的标准 K 线。
3. 在标准 K 线上用严格三 K 线规则识别分型。
4. 分型映射回原始 K 线，并记录核心原始索引。
5. 同类分型连续出现时，只保留更极端的那个。
6. 用新笔定义作为默认成笔标准：不共用 K 线，且核心 K 线之间至少隔 3 根原始 K 线。
7. 只把确认后的笔作为正式输出，最后一笔作为临时延伸对象。

## 18. 一句话结论

缠论里“一笔”的程序化本质，可以归纳为一句话：

在统一精度下，先把原始 K 线去包含，得到标准 K 线；再在标准 K 线上识别顶底分型；再对分型去噪压缩；最后用“不共用 K 线 + 顶底相邻 + 满足间隔要求”的规则，把相邻一顶一底连接起来，这就是自动画笔。
