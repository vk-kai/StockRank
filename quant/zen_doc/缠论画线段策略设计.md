## 4. 设计原则

### 4.1 原则一：线段建立在“笔”之上

线段的最小构件不是 K 线，也不是分型，而是笔。

因此自动画线段的输入必须是已经确认好的笔序列，而不是直接拿 K 线硬画线段。

### 4.2 原则二：先判断“能否形成线段”，再判断“何时结束”

自动画线段分两步：

1. 判断前三笔是否足以构成一个线段起点。
2. 在线段成立后，再判断它是否被真正破坏。

不能把“构成线段”和“线段结束”混成一套逻辑。

### 4.3 原则三：笔破坏不等于线段破坏

这是整个文档最重要的一条。

程序里必须严格区分：

1. `pen_break`: 某反向笔已经刺穿原线段结构
2. `segment_break`: 原线段已经被另一线段确认破坏

很多“古怪线段”其实就是：

1. 先发生了笔破坏
2. 但没有在该方向延伸成有效新线段
3. 于是原线段继续延续

### 4.4 原则四：线段判断必须用“特征序列”

第 65 课给了线段被笔破坏的几何定义，但真正程序上要精确划分线段结束，必须进入第 67、71、78、81 课的特征序列逻辑。

因此工程里建议分两层：

1. `rough_break`: 用笔破坏定义做初筛
2. `strict_finish`: 用特征序列规则确认线段结束

### 4.5 原则五：历史已确认线段尽量不回改

实时画线段时，最后一个线段经常处于“待确认”状态。

建议把线段分成：

1. 已确认线段
2. 候选线段
3. 临时延伸线段

已经确认的历史线段，除非上游笔序列发生变化，否则不要回改。

## 5. 什么叫完整线段

## 5.1 原始定义

原文先给出最基本定义：

1. 线段至少由三笔组成。
2. 这三笔必须有重叠部分。

这里“重叠部分”是指三笔价格区间有共同交集。

如果三笔分别为 `P1, P2, P3`，每笔区间定义为：

```python
interval(P) = [min(P.start_price, P.end_price), max(P.start_price, P.end_price)]
```

那么三笔重叠区间可写为：

```python
overlap_low = max(low1, low2, low3)
overlap_high = min(high1, high2, high3)
has_overlap = overlap_low <= overlap_high
```

只有 `has_overlap == True`，前三笔才有资格构成一个线段。

## 5.2 程序化定义

本文建议把“完整线段”定义为：

1. 由至少三笔构成。
2. 前三笔具有公共重叠区间。
3. 所有笔方向交替。
4. 整个线段方向由第一笔方向决定。
5. 最后一笔方向与第一笔方向相同。
6. 线段结束必须满足特征序列分型条件，而不是仅靠单笔刺穿。

## 5.3 线段方向

线段方向定义非常简单：

1. 第一笔向上，则该线段为向上线段。
2. 第一笔向下，则该线段为向下线段。

原文还强调：

1. 向上线段一定结束于向上笔。
2. 向下线段一定结束于向下笔。
3. 一个线段不可能从底到底，也不可能从顶到顶。

因此程序上可以直接写死：

```python
segment.direction = segment.pens[0].direction
segment.pens[-1].direction == segment.direction
```

## 6.1 分型对应笔

## 6.2 笔构成线段

线段的基本单元是笔。

## 6.3 特征序列分型对应线段结束判断

## 8. 线段起点的形成规则

## 8.1 最低门槛

一段线段的最小形成条件是连续三笔，且前三笔有重叠。

假设笔序列为：

1. `P1`
2. `P2`
3. `P3`

则：

1. `P1.direction == P3.direction`
2. `P2.direction != P1.direction`
3. `P1, P2, P3` 有共同重叠区间

满足后，即可认为从 `P1` 开始形成一条线段。

## 8.2 为什么不是任意三笔

原文明确指出：

1. 连续三笔不一定构成线段。
2. 三笔必须重叠。

因此程序不能只写：

```python
if len(pens) >= 3:
    make_segment()
```

这会产生大量假线段。

## 8.3 线段成立时点

建议定义为：

1. 当第三笔完成，且前三笔重叠时，该线段进入 `active` 状态。
2. 此时线段已经“存在”，但尚未结束。

## 9. 线段的笔破坏定义

第 65 课先给出了“线段被笔破坏”的几何定义。

## 9.1 向上线段的笔破坏

若某线段由向上笔开始，则其分型序列可写为：

```text
d1 g1 d2 g2 d3 g3 ... dn gn
```

如果存在 `j >= i + 2` 且 `dj <= gi`，则向上线段被笔破坏。

程序化理解：

1. 向上线段运行中
2. 后面出现某个底，跌回了足够前面的顶之下
3. 说明原线段结构已被反向笔刺穿

## 9.2 向下线段的笔破坏

若某线段由向下笔开始，则其分型序列可写为：

```text
g1 d1 g2 d2 g3 d3 ... gn dn
```

如果存在 `j >= i + 2` 且 `gj >= di`，则向下线段被笔破坏。

## 9.3 工程作用

笔破坏定义的作用不是直接判定线段结束，而是：

1. 发现“可能的转折区”
2. 启动特征序列级别的线段结束判断

也就是：

```python
if pen_break_detected:
    enter_segment_finish_check()
```

## 10. 为什么笔破坏不等于线段结束

原文反复强调：

1. 线段被笔破坏，不代表线段已经被线段破坏。
2. 线段结束，必须由另一个线段来破坏。

也就是说：

1. 某一反向笔刺穿了当前线段
2. 但后续如果没延伸成新的有效线段
3. 原线段仍可继续延续

程序中一定要避免这个误判：

```python
# 错误逻辑
if pen_break_detected:
    close_segment()
```

正确逻辑应为：

```python
if pen_break_detected:
    if strict_finish_confirmed:
        close_segment()
    else:
        keep_segment_active()
```

## 11. 特征序列定义

这部分是自动画线段最核心的部分。

## 11.1 特征序列的方向

原文规定：

1. 对于以向上笔开始的线段，特征序列由其中所有向下笔构成。
2. 对于以向下笔开始的线段，特征序列由其中所有向上笔构成。

也就是说：

1. 线段方向和特征序列方向相反。
2. 特征序列不是全部笔，而是“与线段方向相反”的那一侧笔。

## 11.2 程序化构造

假设当前线段的笔索引为：

```text
P0, P1, P2, P3, P4, P5, ...
```

若线段方向为 `up`，则特征序列取：

```text
P1, P3, P5, ...
```

若线段方向为 `down`，则特征序列取：

```text
P1, P3, P5, ...
```

形式上一样，但这些笔本身方向与线段方向相反。

## 11.3 特征序列元素如何看成“K 线”

对每个特征元素，取：

```python
high = max(start_price, end_price)
low = min(start_price, end_price)
```

然后就像对普通 K 线一样：

1. 判断包含关系
2. 去包含
3. 识别特征序列分型

## 11.4 标准特征序列

原文明确指出：

1. 特征序列也存在包含关系。
2. 特征序列也需要做“非包含处理”。
3. 处理后的结果称为标准特征序列。

这与画笔里“原始 K 线 -> 标准 K 线”的逻辑完全对应。

因此建议直接复用同一套包含处理函数。

## 12. 特征序列缺口定义

## 12.1 什么叫缺口

特征序列相邻两个元素，如果价格区间没有重合，则称为特征序列缺口。

对两个特征元素 `A`、`B`：

```python
has_gap = min(A.high, B.high) < max(A.low, B.low)
```

更直接地写：

```python
has_overlap = max(A.low, B.low) <= min(A.high, B.high)
has_gap = not has_overlap
```

## 12.2 为什么缺口重要

第 67 课把线段结束分成两种情况，其唯一分界点就是：

特征序列分型中，第一元素和第二元素之间是否存在缺口。

这就是后续所有严格结束判断的入口条件。

## 13. 特征序列分型

## 13.1 识别方式

在标准特征序列上，用和普通分型相同的三元素结构识别。

但注意：

1. 对向上线段，只看特征序列的顶分型。
2. 对向下线段，只看特征序列的底分型。

## 13.2 为什么只看一种分型

因为：

1. 向上线段的结束，关键是反向打击形成“顶分型结构”。
2. 向下线段的结束，关键是反向打击形成“底分型结构”。

这属于线段方向的对称定义。

## 13.3 数据结构落地

识别出特征序列分型后，必须记录：

1. 左元素
2. 中元素
3. 右元素
4. 分型价格
5. 左元素与中元素之间是否有缺口

其中第 5 项是后续区分第一种情况和第二种情况的关键。

## 14. 线段结束的两种情况

这部分是整个自动画线段的核心判定器。

## 14.1 第一种情况

原文规则：

1. 若特征序列分型中，第一元素与第二元素之间不存在缺口
2. 那么线段在该分型高点或低点处结束

程序化理解：

1. 当前线段已经被笔破坏
2. 在同一特征序列中出现了有效特征分型
3. 且该分型左元素与中元素之间没有缺口
4. 这时当前线段在该分型极值处结束

向上线段：

1. 看顶分型
2. 取顶分型中元素高点作为线段终点

向下线段：

1. 看底分型
2. 取底分型中元素低点作为线段终点

## 14.2 第二种情况

原文规则：

1. 若特征序列分型中，第一元素与第二元素之间存在缺口
2. 则还不能直接判线段结束
3. 需要从该分型极值点开始，观察反方向笔序列的特征序列
4. 若后者出现对应分型，则前线段在原分型极值处结束

程序化理解：

1. 当前线段已进入疑似结束状态
2. 但由于左元素和中元素之间存在缺口，说明这是第二种情况
3. 此时必须再观察“第二特征序列”
4. 若第二特征序列出现分型，则原线段确认结束

原文特别强调：

1. 第二种情况下，第二特征序列中的分型不再区分第一、第二种情况
2. 只要有分型即可

## 14.3 第一种和第二种情况的本质区别

第一种情况：

1. 线段结束判断相对直接
2. 同一特征序列内的分型就够了

第二种情况：

1. 同一特征序列内还不够
2. 还要看后续是否延伸出“第二特征序列分型”

所以实现上绝不能把两种情况混成一套。

## 15. 第二特征序列怎么构造

## 15.1 起点

第二特征序列从“原特征分型极值点开始的反向第一笔”开始构造。

也就是说：

1. 对向上线段，在一个顶分型触发第二种情况后
2. 从该顶分型最高点开始的向下笔序列里
3. 重新抽取特征序列
4. 若出现底分型，则原线段结束

向下线段同理反过来。

## 15.2 是否要求回补原缺口

原文明确指出：

1. 第二种情况中，后一特征序列不一定封闭前一特征序列相应的缺口。
2. 只要第二特征序列出现分型即可。

所以代码里不要多加“必须回补前缺口”的额外条件。

## 15.3 为什么还会有人搞错

因为很多人把：

1. 线段被笔破坏
2. 特征序列缺口被回补
3. 线段真正结束

混成同一件事。

实际上三者不是同一个层次。

## 16. 特征序列包含关系的特别注意事项

第 71 课对此讲得非常细。

## 16.1 只允许在同一特征序列内讨论包含

如果两个元素不属于同一特征序列，就不能讨论包含。

这是程序里最容易偷懒写错的地方。

错误写法通常是：

1. 一旦进入候选结束态
2. 就把后面所有同方向元素拿来统一做包含

这是不严谨的。

## 16.2 第一种情况里的“假设分界点两边”

第 71 课强调：

1. 假设转折点前后那两个元素，不一定属于同一特征序列
2. 所以它们之间不能强行做包含处理

因此程序上要区分：

1. 同一特征序列内部元素，可做包含
2. 假设分界点两侧异属元素，不做包含

## 16.3 第二种情况中的第二特征序列

第 78 课强调：

1. 第二种情况中的第二特征序列判断，必须严格按包含关系处理
2. 这里不能省略

所以代码中至少要有两套入口：

1. `build_primary_feature_sequence()`
2. `build_secondary_feature_sequence()`

但底层的包含处理函数可以复用。

## 17. 自动画线段完整流程

下面给出推荐实现流程。

## 17.1 第一步：获取确认笔序列

输入：

1. 笔列表 `pens`
2. 每笔方向、价格区间、端点分型

## 17.2 第二步：扫描前三笔是否构成线段

对 `pens[i:i+3]`：

1. 判断方向是否交替
2. 判断 `pens[i]` 与 `pens[i+2]` 是否同方向
3. 判断三笔是否存在公共重叠
4. 若成立，则初始化新线段

## 17.3 第三步：线段延伸

一旦线段成立：

1. 同方向的末笔不断加入线段
2. 每新增一笔，就检查是否触发笔破坏

## 17.4 第四步：触发严格结束判定

若触发笔破坏：

1. 构造当前线段特征序列
2. 对特征序列做非包含处理
3. 识别特征分型
4. 判断第一元素与第二元素间有无缺口
5. 分别走第一种或第二种情况

## 17.5 第五步：确认线段结束点

若满足结束条件：

1. 在线段终点位置确认该线段
2. 以破坏后方向的笔为起点，尝试构造下一条线段

## 17.6 第六步：若不满足结束条件，则原线段继续

如果：

1. 只是笔破坏
2. 但没有形成线段破坏

则：

1. 原线段保持 `active`
2. 后续笔继续并入原线段的延伸分析

## 18. 推荐伪代码

```python
def build_segments(pens, config):
    segments = []
    i = 0

    while i < len(pens):
        seed = try_seed_segment(pens, i, config)
        if seed is None:
            i += 1
            continue

        segment = seed
        j = seed.end_pen_index + 1

        while j < len(pens):
            segment.pen_indices.append(j)
            segment.end_pen_index = j
            update_segment_range(segment, pens)

            if pen_break_detected(segment, pens):
                finish = try_confirm_segment_finish(segment, pens, config)
                if finish.confirmed:
                    apply_finish(segment, finish, pens)
                    segments.append(segment)
                    i = finish.next_start_pen_index
                    break

            j += 1
        else:
            segment.status = "active"
            segments.append(segment)
            break

    return segments
```

## 19. 关键函数设计

## 19.1 `try_seed_segment()`

职责：

1. 用连续三笔判断是否能形成新线段

判定条件：

1. 至少三笔
2. 方向交替
3. 第一笔和第三笔同方向
4. 三笔重叠

## 19.2 `pen_break_detected()`

职责：

1. 用第 65 课的几何规则判断是否发生笔破坏

输出：

1. `True/False`
2. 首次破坏发生的笔索引

## 19.3 `build_feature_sequence()`

职责：

1. 根据线段方向抽取反向笔
2. 构造成特征序列元素

## 19.4 `normalize_feature_sequence()`

职责：

1. 对特征序列元素做包含处理
2. 输出标准特征序列

## 19.5 `detect_feature_fractal()`

职责：

1. 在标准特征序列中寻找顶分型或底分型
2. 同时记录第一、第二元素间是否存在缺口

## 19.6 `try_confirm_segment_finish()`

职责：

1. 封装第一种与第二种情况的判断
2. 返回是否确认结束及结束位置

返回建议：

```python
class FinishDecision:
    confirmed: bool
    finish_price: float | None
    finish_pen_index: int | None
    finish_mode: str | None     # 'case1' / 'case2'
    next_start_pen_index: int | None
```

## 20. 线段结束判定逻辑细化

## 20.1 第一种情况判定伪代码

```python
def finish_case1(feature_fractal, segment_direction):
    if not feature_fractal.has_gap_between_1_2:
        if segment_direction == "up" and feature_fractal.type == "top":
            return True
        if segment_direction == "down" and feature_fractal.type == "bottom":
            return True
    return False
```

## 20.2 第二种情况判定伪代码

```python
def finish_case2(primary_fractal, segment_direction, pens):
    if not primary_fractal.has_gap_between_1_2:
        return False

    secondary_seq = build_secondary_feature_sequence(primary_fractal, segment_direction, pens)
    secondary_std = normalize_feature_sequence(secondary_seq)
    secondary_fractal = detect_required_secondary_fractal(secondary_std, segment_direction)

    return secondary_fractal is not None
```

## 20.3 第二种情况的程序解释

对向上线段：

1. 先找到主特征序列顶分型
2. 且该分型第一、第二元素间有缺口
3. 再从该顶点开始的向下笔序列中构建第二特征序列
4. 若第二特征序列出现底分型
5. 则原向上线段在主顶分型高点处结束

向下线段同理反过来。

## 21. 线段的实时状态机

建议用状态机写，避免后面变成一堆 if-else。

## 21.1 状态定义

```python
class SegmentState(Enum):
    SEEK_SEED = 1
    ACTIVE = 2
    PEN_BROKEN = 3
    FINISH_CANDIDATE = 4
    CONFIRMED = 5
```

## 21.2 状态说明

### `SEEK_SEED`

等待连续三笔形成线段种子。

### `ACTIVE`

线段已成立，继续延伸。

### `PEN_BROKEN`

已检测到笔破坏，但尚未确认线段结束。

### `FINISH_CANDIDATE`

已出现特征序列分型，正在判断第一种或第二种情况。

### `CONFIRMED`

线段已确认结束。

## 21.3 状态迁移

```text
SEEK_SEED -> ACTIVE
ACTIVE -> PEN_BROKEN
PEN_BROKEN -> FINISH_CANDIDATE
FINISH_CANDIDATE -> CONFIRMED
FINISH_CANDIDATE -> ACTIVE
```

其中：

1. `FINISH_CANDIDATE -> ACTIVE` 表示只是笔破坏，线段并未真正结束。

## 22. 古怪线段的统一解释

第 78 课已经把这个问题说得很透。

所谓“古怪线段”，本质只有一种来源：

1. 发生了第一种类型的笔破坏
2. 但后续没有在该方向延伸成线段破坏
3. 于是原线段继续延续

因此程序中应该把古怪线段视为正常情况，而不是例外情况。

## 23. 线段标准化处理

第 78 课还给了一个对后续中枢分析很重要的建议。

## 23.1 为什么要标准化

有时线段内部最高点或最低点不在端点上。

如果后续做中枢、走势类型分析，把线段当基础部件时，其内部细节并不重要。

因此可以把线段标准化为：

1. 向上线段：以最低点开始，以最高点结束
2. 向下线段：以最高点开始，以最低点结束

## 23.2 程序实现建议

保留两套值：

1. `raw_segment_start / raw_segment_end`
2. `normalized_start / normalized_end`

这样：

1. 画图时可以用原始线段端点
2. 做中枢分析时可以用标准化端点

## 24. 边界场景处理

## 24.1 场景一：三笔但无重叠

处理：

1. 不构成线段。
2. 继续等待后续笔。

## 24.2 场景二：已有笔破坏，但后续无特征分型

处理：

1. 不确认线段结束。
2. 原线段继续。

## 24.3 场景三：第二种情况中找不到第二特征序列分型

处理：

1. 原线段未结束。
2. 不新建后续线段。

这点原文讲得非常明确。

## 24.4 场景四：笔破坏后直接又创新高或新低

处理：

1. 如果没有形成有效新线段，则原线段继续。
2. 不能机械切成三段。

## 24.5 场景五：中间高点看起来像一段，其实只有一笔

处理：

1. 不单独成段。
2. 牢记“笔破坏不等于线段破坏”。

## 24.6 场景六：第三笔完全落在第一笔范围内

第 71 课特别提到这种更复杂情况。

处理：

1. 暂时无法明确方向
2. 继续等待后续是否先突破第一笔结束点或开始点
3. 若先破结束点，则新线段成立
4. 若先破开始点，则原线段延续

## 24.7 场景七：最后一个线段还未完成

处理：

1. 标记为 `active`
2. 前端建议画虚线
3. 不参与严格的历史统计

## 24.8 场景八：数据精度差异导致线段不同

第 81 课特别强调：

1. 对只有几根 K 线的局部结构，极小价差就可能改变整个划分
2. 必须保证使用同一种软件、同一精度口径

因此建议：

1. 线段计算全流程复用画笔层的统一精度配置
2. 不要在线段层重新引入另一套浮点比较规则

## 26. 推荐实现口径总结

如果你现在就要写“自动画线段”代码，我建议直接按下面这套口径落地：

1. 以上游确认笔作为唯一输入。
2. 用连续三笔且三笔重叠作为线段种子条件。
3. 线段方向由第一笔决定，最后一笔方向必须与第一笔相同。
4. 用第 65 课的规则只做“笔破坏检测”，不直接用于结束确认。
5. 用第 67、71、78、81 课的特征序列规则做严格结束判断。
6. 第一种情况看主特征序列分型且第一、二元素间无缺口。
7. 第二种情况看主特征序列分型且第一、二元素间有缺口，再检查第二特征序列是否出现分型。
8. 若只是笔破坏而未满足严格结束，则原线段继续延伸。
9. 对外同时输出原始线段端点和标准化线段端点。
10. 最后一个未完成线段单独标记，不与历史确认线段混用。

## 27. 一句话结论

缠论里“自动画线段”的程序化本质，可以归纳为一句话：

先用确认笔找到“连续三笔且前三笔重叠”的线段种子，再在延伸过程中区分“笔破坏”和“线段破坏”，最后通过特征序列、标准特征序列及其分型，按“第一种情况 / 第二种情况”来确认线段是否真正结束。
